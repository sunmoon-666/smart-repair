# AI 报修建议接口约定

A 负责详情页按钮、加载与重试提示和建议展示。B 负责接口、模型调用与结果保存。

- 已登录的报修小组成员通过 `POST /api/suggest` 请求建议，字段为 `repairId`、`deviceType` 和 `description`。
- 服务端根据登录身份校验报修可见性，再以已保存的设备和故障描述为准生成建议。仅发送生成建议所需的设备和故障信息。
- 成功返回 `{ suggestions: string[] }`，恰好三条可由普通用户安全执行的排查建议。先把建议存入对应报修，再返回成功。刷新详情时通过现有报修接口读取已保存的建议。
- 未登录返回 401，非成员返回 403，输入无效返回 400，找不到可访问的报修返回 404。生成或保存失败返回可重试的错误，保留原报修和已有建议。错误格式沿用 `{ error: { code, message } }`。
- `DEEPSEEK_API_KEY` 由授权持有人在 Vercel 配置。正式合并前，用虚构报修验证生成、保存、刷新读取和未登录访问限制。
